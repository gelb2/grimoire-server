# AI 채팅 기능 연구 — 장기 검토 과제

> 참조: `PLANNING_GRIMOIRE.md` §14 (RAG/Vector AI 창작 지원)
> 상태: 백로그 — Phase 5 이후 검토

---

## 1. 배경

플랫폼에 AI 채팅 기능을 도입하여 작가/독자 경험을 향상시킬 수 있다.
핵심 제약: **API 비용을 최소화**해야 한다.

---

## 2. 유효한 활용 방안

| 기능 | 설명 | API 비용 전략 |
|------|------|-------------|
| 작가 창작 도우미 | 설정 붕괴 체크, 톤 일관성 피드백 (§14) | 크레딧 차감 — 유저가 비용 부담 |
| 독자 Q&A 봇 | 플랫폼 사용법, FAQ 자동 응답 | 저렴한 모델 (Haiku) 사용 |
| CS 1차 대응 | 단순 문의 자동 분류 + 답변 | Haiku + 정형화된 프롬프트 |

---

## 3. 저비용 API 전략

| 전략 | 설명 |
|------|------|
| 모델 티어링 | FAQ → Haiku ($0.25/1M), 창작 → Sonnet ($3/1M), 복잡한 분석 → Opus |
| 캐싱 | 동일 질문 패턴 캐싱 (Redis 또는 DB) |
| 프롬프트 최적화 | 시스템 프롬프트 최소화, few-shot 대신 구조화된 지시 |
| Rate limiting | 유저당 일일 채팅 횟수 제한 |
| 크레딧 연동 | AI 기능은 크레딧 소비 → §0 원가 원칙 적용 |

---

## 4. 기술 아키텍처 (초안)

```
유저 채팅 입력
  → grimoire-server /api/chat
  → 용도 분류 (FAQ / 창작 / CS)
  → 모델 선택 (Haiku / Sonnet)
  → Claude API 호출
  → 응답 + 토큰 사용량 기록
  → credit_logs에 비용 기록
```
